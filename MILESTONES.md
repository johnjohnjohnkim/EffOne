# Milestones: EffOne

Goal: predict current-season F1 qualifying and races (win, podium and top-10 probabilities) and the drivers' and constructors' championships, served through a web app and updated as new sessions finish.
Out of scope: pit-stop strategy and safety-car prediction; training on pre-2018 data; full model retraining on every refresh. Full design and decisions are in `HANDOFF.md`; rules for agents are in `AGENTS.md`.

## 3. Leakage-safe features  [x]
Why: wrong features that peek at the future make every later score meaningless.
Touches: `ml/features/`, `tests/`
Blockers: none
Done-check: `python -m uv run pytest` -> passes, including, for every feature builder, a test that changing data from the target session onward leaves that session's features unchanged. `python -m uv run python -m ml.features` -> writes a feature table to `data/features/` with one row per driver per race and a count of missing values per column.
Report: A leakage-safe feature table exists and `python -m uv run python -m ml.features` writes it: `data/features/race_features.parquet` (3,810 rows = one per driver per race, 189 races 2018 to 2026, 44 drivers) and `feature_missing.csv` (missing count per column, with each column's role). 24 features by default for finish/DNF targets, 21 for qualifying/grid targets (weather is opt-in, see below).
- Done-check: `python -m uv run pytest` -> 226 passed (181 with `-m "not realdata"`); `ruff check` and `ruff format --check` clean. For every feature builder a test scrambles everything from the target session onward (its outcomes, later races' outcomes, even who raced for which team at which circuit) and asserts the target's features are unchanged, on synthetic and real data (races 2019 R5, 2022 R12, 2024 R3, 2025 R3). Further tests: a table cut off at the target race with its outcomes blanked gives identical features (random tables and 3 real races), appending a different future changes nothing, and deliberately broken history slices (including the target, the whole year, everything) are detected.
- Design: a builder receives only the results of races strictly before the target plus the target's entry list, and which target columns it gets depends on its stage (`pre_weekend`: entry list; `scenario`: weather; `post_quali`: grid). It cannot read outcomes it is not given. `features_for_entry(history, entries, key)` builds features for a race with no results at all (the prediction-time path; entries are validated); `features_for_race` adds keys and targets; `training_frame(table, target)` returns only the rows and columns that are safe to train a target on.
- Features (ml/features/builders.py): driver form (last-5 finish/grid/quali/pace, DNF rate, share of season points, rounds since last start), team form (last-5 finish/quali gap/pace, DNF rate, share of points), circuit history (25% rule applied to the race's own entry list, shrunk to recent form; overtaking and DNF rate), context (round, seasons since a regulation change), weather, grid. Teams keep their history across renames via an explicit table (Toro Rosso/AlphaTauri/RB, Force India/Racing Point/Aston Martin, Renault/Alpine, Sauber/Alfa/Audi); Cadillac has none. This lineage table is a judgement from public knowledge, not data.
- Review: 3 rounds with a harsh reviewer agent. Round 1 found no history leakage but several hazards (a stage-blind column list that would hand `grid` to a qualifying model, no prediction-time path, data-quality flags ignored, weak tests). Round 2 found a real leak (next bullet). Round 3 found no blocker; its fixes were applied: expectation-based tie handling, strict `race_ok` validation for the target race and for string-typed flags, one-circuit and duplicate-driver checks, `training_frame`, real-data tests pinned to completed seasons. I deliberately broke the code in 7 + 3 ways (by hand, not scripted) and confirmed the tests failed each time.
- IMPORTANT, a bug in Milestone 2 code that was already pushed: rows were stored in exact finishing order and the evaluation metric broke ties by row order, so a model that outputs the same score for every driver scored Spearman 1.0 and picked the winner 100% of the time. Fixed in two steps: rows are now ordered by driver id (`ml/evaluation/data.py`, `ml/features/tables.py`), and the metrics now treat tied scores by EXPECTATION (tied drivers are equally likely to take any position the tie covers) instead of any tie-break, so results do not depend on row order or on the order a model returns scores (a first fix with a seeded shuffle was neutral on average but noisy, about 0.05 in Spearman). A constant score now gets exactly chance: Spearman 0.0, winner 1/field size. Impact on the reported baselines was negligible because ties are rare for them. Corrected leaderboard (144 races; 2019 to 2024 and 2026 so far; 2025 locked): grid = finish Spearman 0.623, MAE 3.497, winner 0.521, podium 0.674, top-10 0.761; previous race = finish 0.448, 4.434, 0.375, 0.512, 0.682. Any model that produces ties would have been rewarded by the old metric, which is why this had to be fixed before Milestone 4.
- Rules for Milestone 4 (also in the build.py docstring): never sort or order rows by the outcome; `race_ok` (False only for the 2021 Belgian GP) is a TRAINING filter, never a feature and never a test filter (it is derived from the race's own results); use `feature_columns(target)` or `training_frame`, which exclude `grid` for qualifying/grid targets and weather unless `include_scenario=True`; report results with and without weather, because history holds the realised race-day weather whereas a prediction only has a forecast. Models should wrap `features_for_entry` inside `predict_race(history, race)`. The harness still builds its history from raw results (`load_race_results`), so it counts the 2021 Belgian GP and drops rows with an unknown finish; Milestone 4 plans to switch it to `build_history`, which has `TeamKey`, `CircuitId` and `race_ok`.
- Needs your decision: the 2021 Belgian GP (R12) is now treated as "not a race" (`NOT_A_RACE` in ml/features/tables.py): its finishing order equals the grid and it has half points, so it feeds no form or circuit history; its rows stay in the table with `race_ok` False. This was my default while you were away; remove the entry to count it again. Side effect: its genuine qualifying session is also ignored.
- Known and deferred: (1) `circ_drv_finish` averages raw finishes from different years (car strength mixes in) and its prior overlaps the visits; (2) no driver wet-weather skill, so weather alone has about zero signal; (3) per-race-constant features (weather, round, circuit rates, `seasons_since_reg_change`) can act as race identifiers for tree models; (4) NaN semantics need a documented imputation in Milestone 4 (points share is NaN at round 1, rounds-since-last NaN for debutants); (5) 2026 calendar oddities ('kuala_lumpur' Bahrain GP, 'madrid') still unmapped; (6) sprint points are not in the points share; (7) the entry list for past races includes late substitutes; (8) the leakage scramble does not vary who is in the target race's entry list.

- STOP RULE, strict reading: the command exits with code 3 because on the QUALIFYING board no model clearly beats the best baseline. Be careful what this means. Models beat the two "repeat the last result" baselines by a wide margin, but a trivial "average of the driver's last 5 results" baseline (no model, no features) scores 0.740 and the best models reach 0.751: a gain of about +0.011, which is inconclusive, not zero (ridge +0.011, season-clustered interval [-0.001, 0.024], ahead in 5 of 7 seasons). Whether that counts as "clearly" depends on the interval method (a one-stage bootstrap over the season means would put it just above zero, a t-interval just below), so exit code 3 is the conservative outcome rather than a finding that the models add nothing. It is a result to discuss, and it is why the loop stops here.
- Models (ml/models/): ridge, random forest, LightGBM, XGBoost, LightGBM LambdaRank, XGBoost pairwise ranking, Elo (driver + team ratings replayed from history, no features), Plackett-Luce (own implementation, maximum likelihood on whole finishing orders), plus `lightgbm_with_weather` for the race target and `[no grid]` variants for the pre-qualifying forecast. All use the leakage-safe features through `features_for_entry`; they are fitted once per test season on earlier seasons only (not refit during the season).
- Comparison method: every model is compared with the best baseline on the same races. "Clearly beats" means the 95% interval for the gain in mean Spearman lies above zero, using a SEASON-CLUSTERED bootstrap (resample seasons, then races within them), because races in a season are alike; with only seven seasons even this interval is rough. The plain race-level interval is also saved, and each row shows in how many of the 7 seasons the model beats the baseline. Ties in predictions AND in actual positions are scored by expectation, so nothing depends on row order. Baselines (all use only races that carried real information): race = grid equals finish, previous race, average of last 5 finishes; qualifying = previous qualifying, previous race result, average of last 5 qualifying results.
- Results (mean Spearman; gain over best baseline with the season-clustered 95% interval; seasons won):
  - QUALIFYING (best baseline: average of last 5 qualifying positions, 0.740): ridge 0.751 (+0.011 [-0.001, 0.024], 5/7 seasons), Elo 0.751 (+0.011 [-0.005, 0.026], 5/7), random forest 0.750, Plackett-Luce 0.750, XGBoost rank 0.745, LightGBM 0.745, XGBoost 0.743, LambdaRank 0.742. None clearly beats it. Previous qualifying (0.660) and previous race (0.547) are beaten by every model by a wide margin, but that mostly shows the single-result baselines are weak. Elo uses no features at all and ties the best model.
  - RACE with the real grid (best baseline: grid equals finish, 0.623, winner right 52.1%): ridge 0.663 (+0.040 [0.016, 0.067], 7/7 seasons, winner 54.2%), random forest 0.660 (+0.037 [0.012, 0.063], 7/7) and LightGBM LambdaRank 0.654 (+0.031 [0.001, 0.063], 5/7, only just, and see the post-hoc note) clearly beat it. LightGBM 0.643 (6/7), LightGBM with weather 0.644, XGBoost 0.639, Plackett-Luce 0.634 and XGBoost rank 0.628 cannot be told apart from it; Elo 0.605 (it never sees the grid) is below it; the average of the last 5 finishes is 0.564 and the previous race 0.447.
  - RACE BEFORE QUALIFYING (best baseline: the predicted grid taken as the result, 0.606): nothing beats it. Chained models: ridge (0.609) and random forest (0.605) tie it; XGBoost is clearly worse (-0.022 [-0.053, -0.001]); LightGBM (-0.016 [-0.035, 0.000]) and XGBoost rank are borderline; LambdaRank and Plackett-Luce are below without a clear gap. These models were trained on real grids, which are far more informative than predicted ones. Models built without any grid: ridge (0.609), random forest (0.604) and Elo (0.605) tie the baseline, LightGBM (0.585) is borderline worse, Plackett-Luce (0.572) is clearly worse, and the naive no-grid baselines are clearly worse (average of last 5: 0.564, previous race 0.447).
  - Weather: LightGBM with weather 0.644 versus without 0.643, so no measurable gain; it stays opt-in and is not used on the pre-qualifying board.
- What the numbers say: (1) at this data size (about 3,000 training rows) simple form averaging, Elo and ridge are as good as boosted trees or rankers, and none of the complex models adds a clear gain; (2) the starting grid carries most of the race signal; (3) a forecast before qualifying is therefore capped near the qualifying forecast itself (Spearman about 0.6); (4) with 144 races in 7 seasons, differences under about 0.02 are noise, so do not read the order among the top models.
- Post-hoc choices, disclosed: the `[no grid]` variants and the weather comparison were added after seeing the first race-board results; the LambdaRank label gain was changed from LightGBM's exponential default to linear after the default was seen to underperform (0.723 to 0.742 for qualifying, 0.632 to 0.654 for the race), so LambdaRank's race result is optimistic and its "clearly beats" is marginal (it does not survive a stricter multiple-comparison interval). Hyperparameters were set by hand and never searched, but their provenance was not logged and they were chosen with these seasons in view, so treat all numbers as mildly optimistic. There is no separate validation scheme; the reported seasons were both used to look and to report. Models for 2026 train on 2025, the locked season, which is legitimate but means any later look at 2025 is not fully fresh.
- Review: two rounds with a harsh reviewer agent. It reproduced every number and found no leakage (it recomputed features for 189 races from strictly earlier history: 0 mismatches; it also showed baseline scores are unchanged by handing models the full entry list). Round 1 found: a weak baseline, race-level intervals that were too narrow, a stop rule that could never fire, undisclosed post-hoc variants, the LambdaRank gain, Elo not shrinking at the first race of a season, ties broken by row order, models being handed an entry list filtered by the result, silent dropping of uneven coverage in the bootstrap, and missing guards. Round 2 found: a docstring that still said "not tuned", a selective reading of the predicted-grid board, a qualifying exit-code framing that was stronger than the evidence, tied ACTUAL positions being scored wrongly (a tied pole gave a perfect predictor 0% winner credit), the new baseline not being strict about `race_ok`, the pre-qualifying board containing a realised-weather model, and weak tests. All were fixed.
- Tests: `python -m uv run pytest` -> 331 passed (286 without the real-data ones); `ruff` clean. Interface, determinism and refit-skip tests for every model on both targets; a leakage test per model (fit on earlier seasons, destroy everything from the target race on, same predictions); user-supplied-grid and predicted-grid tests (the race model accepts either; the qualifying model never receives the grid; tied qualifying scores share a grid slot; a late non-starter with no grid or result is handled end to end); Elo (ignores races at or after the target, first-race shrink, strict race_ok); Plackett-Luce likelihood against brute force, finite-difference gradient, direction of the learned signal, convergence flag; training-data errors; bootstrap (clustered wider than race-level, uneven coverage rejected, one lucky season is not "clear"); baselines (mean of last 5, non-races and bad flags); metrics (constant score gets chance, ties on both sides); harness (entry columns per target, full entry list handed to models, only known outcomes scored); CLI (three leaderboards, locked season, exit code agrees with the saved leaderboard, predicted-grid board informational). - 4b.1: 146 trials (8 models x quali and race), scored on 2019-2021 only; trial log and chosen settings are in `ml/models/`. Winners are shallow and strongly regularised (depth 2-4, 4 leaves, large leaf minimums, ridge alpha 30-300), i.e. the search preferred less flexible models. On report seasons (2022-24, 2026), qualifying: best model elo 0.733 Spearman, 4/4 seasons better than the best baseline, +0.028 over mean-of-last-5 (M4 untuned: about +0.011). Race (with real grid): ridge 0.670, +0.049 over the best baseline. Caveat: these seasons were seen in M4, so some of the gain could be luck of the search selecting on dev; 2025 stays locked as the real test.
- 4b.2: same-weekend (`pq_`) features, a `post_practice` stage that models must opt into. Session availability is by scheduled start time; the rule is pinned by tests for all four weekend formats and checked against every real weekend 2018-2026 (0 violations). New board `quali_after_practice`: best model plackett_luce 0.765 Spearman vs mean-of-last-5 0.705 (+0.060, clustered 95% interval [0.034, 0.090], 4/4 seasons); the naive "practice order = qualifying order" baseline is 0.688. Not yet tuned separately (uses the qualifying settings), and 2026 weekends with missing practice data fall back to NaN.

- 4b.3: a gap-to-pole target (`y_qgap`) and recency-weighted form (half-lives 2, 4, 8 races; opt-in) were tuned per model on 2019-2021 only (32 trials via `ml.tuning --features`). On the report seasons (2022-24, 2026; 84 races) the tuned variants did NOT beat the plain models: ridge 0.724 vs ridge+gap 0.716, random forest 0.729 vs +gap 0.719, xgboost 0.729 vs +gap+ew2 0.725; every variant scored below its own plain model. (All three are not alike against the baseline: xgboost+gap+ew2 is still clearly above it, CI [0.004, 0.037], while ridge+gap and random_forest+gap are not; but that is because the baseline is weak, not a sign the variant helps.) Only each model's interval against the baseline was computed, not a paired plain-versus-variant interval, so "worse" here means lower point estimate, not a significant loss. So the plain features and rank target stay the default and the new options stay opt-in and unused. Development-season gaps between configurations were about 0.005 Spearman, i.e. the choices were noise-fitting. Best qualifying models are unchanged: Elo 0.733, xgboost and random forest 0.729.
- 4b.4: `OutOfFoldGridRace` trains each race model on walk-forward predicted grids (every season is predicted by a LightGBM qualifying model fitted on earlier seasons only), then feeds it a predicted grid at forecast time, so training and use match. The first training season has no earlier one; that split falls back to real grids and the model records it (`fell_back`). Pre-qualifying board (race_predicted_grid, report seasons): ridge [oof grid] 0.620 vs ridge [predicted grid] 0.617; xgboost_rank 0.617 vs 0.612; random forest 0.614 vs 0.613; the other models move by under 0.01 in either direction. No model clearly beats the best baseline (predicted grid = finish, 0.611) on the 95% season-clustered interval. Reading it carefully: the intervals quoted are each model's gain over the baseline, not oof versus predicted-grid (no paired interval was computed). Per season, ridge oof minus ridge predicted grid is +0.011 (2022), +0.003 (2023), -0.002 (2024), -0.0002 (2026): the whole gain is one season. The comparison is also confounded: the oof models cannot train on the first training season (2018 has no earlier season), so they learn from one fewer season than the predicted-grid models. So this is "no clear evidence that out-of-fold grids help", not proof that the train/use mismatch is irrelevant; the pre-qualifying forecast still appears capped by the qualifying forecast (about 0.6-0.7). The first split of a `--seasons dev` or `all` run (2019, one training season) falls back to real grids and now emits a warning; report-season runs never hit it. The locked 2025 season is used as TRAINING data for the 2026 split (by design) but was never scored. Review: a reviewer subagent found no leakage, and these fixes were made from its findings: tests that did not catch a race model trained on real grids, a cache key that would have served stale grids for a partly-played season, a recency-age test that could not fail, a vacuous scramble test, and the claims above.
